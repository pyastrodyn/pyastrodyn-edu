## twobody

File `pyastrodyn_edu/twobody.py`. Lecture 1. [Back to the map](#map-of-the-library).

The Keplerian restricted two-body problem: equation of motion and integrals.

Layer 2 (numerical). Any consistent unit system. Vectors are given by their
components in an inertial basis N, with shape (3,) for one state or (n, 3)
for n states.

NUMERICAL INTEGRATION, IN BRIEF
-------------------------------
The equation of motion  r'' = -mu r / |r|^3  is of second order. Integrators
want first order, so we stack position and velocity into one state vector

    x = [ r ; v ]   (6 numbers),      x' = [ v ; -mu r / |r|^3 ].

Integrating this Cartesian form directly is known as COWELL'S METHOD. Two
integrators are offered:

- `propagate_numerical`: an adaptive integrator from SciPy (default DOP853,
  a Dormand-Prince Runge-Kutta method of order 8). It chooses its own step
  size so that the estimated error of each step stays below a tolerance.
- `propagate_rk4`: the classical fixed-step Runge-Kutta method of order 4,
  written out in full so that every operation can be read.

| Function | What it does |
|---|---|
| [`twobody_eom`](#twobody_eom) | Right-hand side of the two-body equation of motion, in first-order form. |
| [`propagate_numerical`](#propagate_numerical) | Numerical integration of the two-body equation of motion (adaptive step). |
| [`rk4_step`](#rk4_step) | One step of the classical Runge-Kutta method of order 4 for the two-body problem. |
| [`propagate_rk4`](#propagate_rk4) | Fixed-step integration of the two-body problem with `rk4_step`. |
| [`angular_momentum`](#angular_momentum) | Specific angular momentum vector, h = r x v. |
| [`eccentricity_vector`](#eccentricity_vector) | Eccentricity vector: points to the periapsis, magnitude e. |
| [`specific_energy`](#specific_energy) | Specific mechanical energy, v^2/2 - mu/r. |
| [`gravitational_acceleration`](#gravitational_acceleration) | Magnitude of the gravitational acceleration at a distance from the centre of attraction. |

### twobody_eom

`twobody_eom(t, x_N, mu)`

Right-hand side of the two-body equation of motion, in first-order form.

**Parameters**

- `t` (float)
  Time. Not used (the system is autonomous); present because numerical
  integrators expect the signature `f(t, x)`.
- `x_N` (ndarray, shape (6,) or (n, 6))
  State: position then velocity, components in N.
- `mu` (float)
  Gravitational parameter.

**Returns**

- `xdot_N` (ndarray, same shape as `x_N`)
  Velocity, then acceleration `-mu r / |r|^3`.

**References**

Curtis, *Orbital Mechanics for Engineering Students*; Vallado,
*Fundamentals of Astrodynamics and Applications*.
Lecture 1, hypotheses and equation of motion.

### propagate_numerical

`propagate_numerical(r0_N, v0_N, t_eval, mu, rtol=1e-11, atol=None, method='DOP853')`

Numerical integration of the two-body equation of motion (adaptive step).

**Parameters**

- `r0_N, v0_N` (ndarray, shape (3,))
  Initial position and velocity at time 0 (one trajectory per call).
- `t_eval` (ndarray, shape (m,))
  Increasing, non-negative times at which the state is returned.
- `mu` (float)
  Gravitational parameter.
- `rtol` (float)
  Relative tolerance per step. Default 1e-11.
- `atol` (float, ndarray of shape (6,), or None)
  Absolute tolerance per step. Default (None): 1e-13 times the initial
  distance for the position components and 1e-13 times the initial
  speed for the velocity components.
- `method` (str)
  Integration method of SciPy's `solve_ivp`. Default "DOP853";
  "RK45" (Dormand-Prince, order 5) is a common lower-order choice.

**Returns**

- `r_N, v_N` (ndarray, shape (m, 3))
  Position and velocity at the requested times.

**References**

Curtis, *Orbital Mechanics for Engineering Students*; Vallado,
*Fundamentals of Astrodynamics and Applications*.
Lecture 1, hypotheses and equation of motion.

**Notes**

How the accuracy is controlled. At every step the integrator estimates
its own error, component by component, and accepts the step only if

    error <= atol + rtol * |value of that component|.

Otherwise it repeats the step with a smaller step size. Three points:

- SciPy's own defaults (rtol = 1e-3, atol = 1e-6) are far too loose for
  orbits: on the test orbit below they leave an error of several
  kilometres after ONE revolution with this method, and of tens of
  kilometres with SciPy's default method, RK45. The defaults here are
  much tighter.
- The default `atol` is tied to the size of the initial state, so the
  result is the same in km and s as in canonical units.
- The tolerances bound the error of EACH STEP, not the error at the end,
  which accumulates along the trajectory. Measured against the exact
  Kepler solution on an Earth orbit with a = 11000 km and e = 0.35, the
  position error with the defaults is about 1 mm after 1.5 revolutions,
  0.2 m after 10 and 25 m after 100: it grows roughly with the square of
  the number of revolutions.

`rtol` cannot usefully be set below about 1e-13 (the limit of double
precision).

### rk4_step

`rk4_step(x_N, h, mu)`

One step of the classical Runge-Kutta method of order 4 for the two-body problem.

**Parameters**

- `x_N` (ndarray, shape (6,) or (n, 6))
  State (position then velocity) at the start of the step.
- `h` (float)
  Step size (time).
- `mu` (float)
  Gravitational parameter.

**Returns**

- ndarray, same shape as `x_N`
  State at the end of the step.

**References**

Vallado, *Fundamentals of Astrodynamics and Applications*.
Lecture 1, hypotheses and equation of motion.

**Notes**

The error of one step is proportional to h^5, and the error accumulated
over a fixed time span to h^4: halving the step divides the error by
about sixteen. The time does not appear because the equation of motion
does not depend on it.

### propagate_rk4

`propagate_rk4(r0_N, v0_N, h, n_steps, mu)`

Fixed-step integration of the two-body problem with `rk4_step`.

A teaching integrator: every operation is visible, and the effect of the
step size on the accuracy can be measured directly. For accurate work use
`propagate_numerical`.

**Parameters**

- `r0_N, v0_N` (ndarray, shape (3,))
  Initial position and velocity at time 0.
- `h` (float)
  Step size.
- `n_steps` (int)
  Number of steps; the final time is `n_steps * h`.
- `mu` (float)
  Gravitational parameter.

**Returns**

- `t` (ndarray, shape (n_steps + 1,))
  Times, from 0 to `n_steps * h`.
- `r_N, v_N` (ndarray, shape (n_steps + 1, 3))
  Position and velocity at those times (row 0 is the initial state).

**References**

Vallado, *Fundamentals of Astrodynamics and Applications*.
Lecture 1, hypotheses and equation of motion.

**Notes**

No error control: the accuracy depends entirely on the step size chosen
by the user. As a guide, measured with a step of 1/100 of the orbital
period: the position error after one revolution is a few millionths of
the semi-major axis for e up to 0.2, but about a thousand times larger
for e = 0.6. A fixed step wastes effort far from the focus and is too
coarse near periapsis, which is why adaptive integrators exist.

### gravitational_acceleration

`gravitational_acceleration(r, mu)`

Magnitude of the gravitational acceleration at a distance from the centre of attraction.

**Parameters**

- `r` (float or ndarray)
  Distance from the centre of the attracting body.
- `mu` (float)
  Gravitational parameter.

**Returns**

Valid outside a body with spherical symmetry.

## conics

Layer 2 (numerical). Every function works in any consistent unit system.
Every argument may be one value or an array of n values; the result has the
matching shape. Angles are in radians.

HOW TO READ THIS MODULE: each function is one formula, stated in its
documentation string and written in one or two lines of code. Nothing here
depends on the shape of the inputs: NumPy applies the formula to every value
(primer 1). `np.asarray(x, float)` only turns a list or an integer into an
array of decimal numbers.

Accuracy: all functions are closed-form and accurate to floating-point

## anomalies

File `pyastrodyn_edu/anomalies.py`. Lectures 3 and 4. [Back to the map](#map-of-the-library).

True, eccentric and mean anomaly of the elliptical orbit; Kepler's equation.

Symbols: `f` true anomaly, `E` eccentric anomaly, `M` mean anomaly, all
in radians. Valid for 0 <= e < 1. Every argument may be one value or an array
of n values.

The conversions keep the revolution count: an anomaly of 2 pi + x is mapped to
2 pi + (the image of x), so angles that grow with time stay continuous.

THE THREE ANOMALIES
-------------------
    f  true anomaly:      the real angle at the focus, from periapsis to the
                          spacecraft. Not uniform in time.
    E  eccentric anomaly: an auxiliary angle at the centre of the ellipse,
                          which makes the geometry simple: r = a (1 - e cos E).
    M  mean anomaly:      M = n (t - t_periapsis), uniform in time; an angle
                          only in name.

    f  <-- geometry -->  E  <-- Kepler's equation -->  M  <-- n -->  time

FIRST READING: `single_state.M2E_single` solves Kepler's equation for one
value with an ordinary loop. `M2E` here does the same for many values.

| Function | What it does |
|---|---|
| [`f2E`](#f2e) | Eccentric anomaly from the true anomaly. |
| [`E2f`](#e2f) | True anomaly from the eccentric anomaly. |
| [`E2M`](#e2m) | Mean anomaly from the eccentric anomaly: Kepler's equation, M = E - e sin E. |
| [`M2E`](#m2e) | Eccentric anomaly from the mean anomaly: numerical solution of Kepler's equation. |
| [`f2M`](#f2m) | Mean anomaly from the true anomaly (through the eccentric anomaly). |
| [`M2f`](#m2f) | True anomaly from the mean anomaly (solves Kepler's equation). |

### f2E

`f2E(f, e)`

Eccentric anomaly from the true anomaly.

**References**

Curtis, *Orbital Mechanics for Engineering Students*; Vallado,
*Fundamentals of Astrodynamics and Applications*; for the form used
here, Broucke and Cefola, "A note on the relations between true and
eccentric anomalies in the two-body problem" (1973).
Lecture 3, eccentric anomaly.

**Notes**

Uses E = f - 2 atan(beta sin f / (1 + beta cos f)), with
beta = e / (1 + sqrt(1 - e^2)), which has no quadrant ambiguity.

### E2f

`E2f(E, e)`

True anomaly from the eccentric anomaly.

**References**

Curtis, *Orbital Mechanics for Engineering Students*; Vallado,
*Fundamentals of Astrodynamics and Applications*; for the form used
here, Broucke and Cefola, "A note on the relations between true and
eccentric anomalies in the two-body problem" (1973).
Lecture 3, eccentric anomaly.

**Notes**

Uses f = E + 2 atan(beta sin E / (1 - beta cos E)), with
beta = e / (1 + sqrt(1 - e^2)).

### E2M

`E2M(E, e)`

Mean anomaly from the eccentric anomaly: Kepler's equation, M = E - e sin E.

**References**

Curtis, *Orbital Mechanics for Engineering Students*; Vallado,
*Fundamentals of Astrodynamics and Applications*.
Lecture 4, mean anomaly and Kepler's equation.

### M2E

`M2E(M, e, tol=1e-13, max_iter=50)`

Eccentric anomaly from the mean anomaly: numerical solution of Kepler's equation.

**Parameters**

- `M` (mean anomaly, radians (any value; the revolution count is kept))
- `e` (eccentricity, 0 <= e < 1)
- `tol` (the iteration stops when every correction is below `tol` radians)
- `max_iter` (maximum number of iterations)

**Returns**

- E such that E - e sin E = M

**References**

Curtis, *Orbital Mechanics for Engineering Students*; Vallado,
*Fundamentals of Astrodynamics and Applications*.
Lecture 4, numerical solution and algorithmic aspects.

**Notes**

Newton's method on the mean anomaly reduced to [-pi, pi]. Starting value:
M for e < 0.8, otherwise pi with the sign of M, from which the iteration
converges for every e < 1. Raises `RuntimeError` if `max_iter` is
reached.

### f2M

`f2M(f, e)`

Mean anomaly from the true anomaly (through the eccentric anomaly).

**References**

Curtis, *Orbital Mechanics for Engineering Students*.
Lecture 4, mean anomaly and Kepler's equation.

### M2f

`M2f(M, e, tol=1e-13, max_iter=50)`

True anomaly from the mean anomaly (solves Kepler's equation).

**References**

Curtis, *Orbital Mechanics for Engineering Students*.
Lecture 4, position as a function of time.

## kepler

File `pyastrodyn_edu/kepler.py`. Lecture 4. [Back to the map](#map-of-the-library).

Position as a function of time on an elliptical orbit.

Valid for 0 <= e < 1. Any consistent unit system; angles in radians. Every

## rotations

File `pyastrodyn_edu/rotations.py`. Lecture 5. [Back to the map](#map-of-the-library).

Direction cosine matrices (DCMs).

THE CONVENTION (passive), fixed for the whole library
-----------------------------------------------------
`C_BA` reads "to B, from A". It takes the components of a vector in basis A
and returns the components of THE SAME vector in basis B:

    v_B = C_BA @ v_A

Nothing rotates. The vector stays where it is; only its description changes,
because we look at it from another basis. That is why this module has a
function called `change_basis` and none called "rotate".

A BASIS (in the slides of the course: vector base) is a set of three
mutually orthogonal unit vectors, fixed in a frame. It is not a frame (the
reference with respect to which motion is measured) and not a Cartesian
coordinate system (an origin together with a basis). See the conventions in
the README.

Basis letters: N inertial, P perifocal, H Hill (axis 1 radial, axis 2
transverse, axis 3 along the orbital angular momentum), E Earth-fixed.

SHAPES
------
An angle may be one value or an array of n values. A DCM is then (3, 3) for
one state or (n, 3, 3) for n states: a stack of n matrices.

- One state: plain matrix algebra works, `v_B = C_BA @ v_A`.
- Many states: use `change_basis(C_BA, v_A)`, which pairs matrix k with
  vector k.

## elements

|---|---|

| [`rv2coe`](#rv2coe) | Classical orbital elements from position and velocity. |
| [`coe2equinoctial`](#coe2equinoctial) | Modified equinoctial elements from the classical elements. |
| [`equinoctial2coe`](#equinoctial2coe) | Classical elements from the modified equinoctial elements. |

### coe2rv

`coe2rv(a, e, i, raan, argp, f, mu)`

Position and velocity from the classical orbital elements.

**Parameters**

- `a, e, i, raan, argp, f` (float or ndarray, shape (n,))
  Classical elements. `a` is negative for a hyperbola.
- `mu` (float)
  Gravitational parameter.

**Returns**

- `r_N, v_N` (ndarray, shape (3,) or (n, 3))
  Components in the inertial basis N.

**References**

Curtis, *Orbital Mechanics for Engineering Students*; Vallado,
*Fundamentals of Astrodynamics and Applications*.
Lecture 5, conversion between the state and the orbital elements.

**Notes**

Valid for the ellipse and the hyperbola; not for the parabola (`a`

singular cases see `rv2coe`: the two functions use the same
conventions, so they are exact inverses of each other there too.

### rv2coe

`rv2coe(r_N, v_N, mu, tol=1e-10)`

Classical orbital elements from position and velocity.

**Parameters**

- `r_N, v_N` (ndarray, shape (3,) or (n, 3))
  Position and velocity, components in the inertial basis N.
- `mu` (float)
  Gravitational parameter.
- `tol` (float)
  An orbit is treated as circular if e < tol, and as equatorial if the
  node vector is shorter than tol times the angular momentum.

**Returns**

- `a, e, i, raan, argp, f` (float or ndarray, shape (n,))
  Angles in radians; `raan`, `argp` and `f` in [0, 2 pi).

**References**

Curtis, *Orbital Mechanics for Engineering Students*; Vallado,
*Fundamentals of Astrodynamics and Applications*.
Lecture 5, orbital elements and their singularities.

**Notes**

Singular cases, selected state by state (a mixed set of states is
handled in one call):

- circular, inclined: `argp = 0` and `f` is the argument of latitude
  (angle from the ascending node to the position);
- elliptical, equatorial: `raan = 0` and `argp` is the longitude of
  periapsis (angle from axis 1 of N to the periapsis, measured in the
  direction of motion);
- circular, equatorial: `raan = 0`, `argp = 0` and `f` is the true
  longitude (angle from axis 1 of N to the position).

For the parabola the returned `a` is infinite. Closed-form: accurate
to floating-point rounding, except that close to a singular case (e or
the node vector comparable with `tol`) the angles `raan`, `argp`
and `f` lose accuracy individually, while their sum does not.

### coe2equinoctial

`coe2equinoctial(a, e, i, raan, argp, f)`

Modified equinoctial elements from the classical elements.

**Returns**

- `p, ex, ey, hx, hy, L` (float or ndarray, shape (n,))
  `p = a (1 - e^2)`; `ex = e cos(raan + argp)`,
  `ey = e sin(raan + argp)`; `hx = tan(i/2) cos(raan)`,
  `hy = tan(i/2) sin(raan)`; true longitude `L = raan + argp + f`,
  in [0, 2 pi).

**References**

Vallado, *Fundamentals of Astrodynamics and Applications*.
Lecture 5, orbital elements (classical, their singularities, equinoctial).

**Notes**

This is the MODIFIED equinoctial set. It differs from the classical
(direct) equinoctial set in two elements: the first is the semi-latus
rectum p in place of the semi-major axis a, and the last is the TRUE
longitude L in place of the mean longitude. The four middle elements are
the same quantities in both sets. The modified set is regular for
circular and for equatorial orbits, and also valid for the hyperbola; it
is singular only for i = pi (retrograde equatorial).

### equinoctial2coe

`equinoctial2coe(p, ex, ey, hx, hy, L)`

Classical elements from the modified equinoctial elements.

**Returns**

- `a, e, i, raan, argp, f` (float or ndarray, shape (n,))

**References**

Vallado, *Fundamentals of Astrodynamics and Applications*.
Lecture 5, orbital elements (classical, their singularities, equinoctial).

**Notes**

Where the classical set is singular the split of the true longitude into
`raan`, `argp` and `f` is a convention: `raan = 0` for an
equatorial orbit and `argp = -raan` (modulo 2 pi) for a circular one.
The state obtained with `coe2rv` is correct in every case.

## lagrange

File `pyastrodyn_edu/lagrange.py`. Lecture 5. [Back to the map](#map-of-the-library).

Lagrange coefficients: the state at a later point from the initial state.

On a Keplerian orbit the position and velocity at any point are linear
combinations of the initial position and velocity,

    r = F r0 + G v0,        v = Fdot r0 + Gdot v0.

Here the coefficients are written in terms of the change of true anomaly,
`df`. Valid for every conic. Any consistent unit system; angles in radians.

| Function | What it does |
|---|---|
| [`lagrange_coefficients`](#lagrange_coefficients) | Lagrange coefficients for a change `df` of the true anomaly. |
| [`propagate_lagrange`](#propagate_lagrange) | Position and velocity after a change `df` of the true anomaly. |

### lagrange_coefficients

`lagrange_coefficients(r0_N, v0_N, df, mu)`

Lagrange coefficients for a change `df` of the true anomaly.

**Parameters**

- `r0_N, v0_N` (ndarray, shape (3,) or (n, 3))
  Initial position and velocity (components in any one basis).
- `df` (float or ndarray)
  Change of true anomaly, radians. One state may be combined with m
  values of `df`.
- `mu` (gravitational parameter)

**Returns**

- `F, G, Fdot, Gdot` (float or ndarray)

**References**

Curtis, *Orbital Mechanics for Engineering Students*.
Lecture 5, Lagrange coefficients.

**Notes**

The four coefficients satisfy `F * Gdot - G * Fdot = 1` (conservation
of the angular momentum). The expression used for `Fdot` has no
division by `sin(df)`, so it is regular for every `df`.

## units

File `pyastrodyn_edu/units.py`. Lecture 3, scaling. [Back to the map](#map-of-the-library).

Scaling of the equations: unit systems and canonical units.

The functions of the library carry no unit of their own: they are correct in
any consistent set of length unit, time unit and `mu`. This module provides
the conversion between two such sets, in one place.

Rule of use: a script chooses its unit system once, converts its inputs at the
start and its outputs at the end, and never mixes systems in between.

### UnitSystem

Class. Created with `UnitSystem(length, time)`.

A consistent pair of length unit and time unit.

**Parameters**

- `length` (float)
  The length unit, expressed in the base length unit (km in this library's
  constants).
- `time` (float)
  The time unit, expressed in the base time unit (s).

**Examples**

Canonical units of a low Earth orbit, in which `mu = 1`:

```python
>>> from pyastrodyn_edu.constants import MU_EARTH
>>> canonical = UnitSystem.canonical(MU_EARTH, 6778.0)
>>> float(round(canonical.nondim(MU_EARTH, "mu"), 12))
1.0
```

**References**

Vallado, *Fundamentals of Astrodynamics and Applications*.
Lecture 3, scaling of the equations.

#### UnitSystem.canonical

`UnitSystem.canonical(mu, r_ref)`

Canonical units: length unit `r_ref`, time unit such that `mu = 1`.

The time unit is `sqrt(r_ref**3 / mu)`. A circular orbit of radius
`r_ref` then has speed 1 and period 2 pi.

#### UnitSystem.unit

`UnitSystem.unit(kind)`

Size of the unit of the given kind, in base units.

`kind` is one of "length", "time", "speed", "acceleration", "mu".

#### UnitSystem.nondim

`UnitSystem.nondim(value, kind)`

Convert a value from base units into this unit system.

#### UnitSystem.dim

`UnitSystem.dim(value, kind)`

Convert a value from this unit system back into base units.

### Problem

Class. Created with `Problem(id, lecture, title, statement, given, solve, result_units, inspired_by, verification, digits=7, rtol=1e-09)`.

One validation problem.

#### Problem.values

`Problem.values()`

The given data as a plain `{name: value}` dictionary.

#### Problem.results

`Problem.results()`

Solve the problem with the library.

### get

`get(problem_id)`

Return the problem with the given identifier, for example "L4-1".

### expected

`expected()`

The stored expected results of all problems, `{id: {name: value}}`.

### compare

`compare(problem_id, data, results)`

Compare the results of an example with the stored results of its problem.

Used in the last section of every example script and notebook.

**Parameters**

- `problem_id` (str)
  Identifier of the problem, for example "L4-1".
- `data` (dict)
  The given data used in the example, `{name: value}`, with the names
  of `get(problem_id).given`.
- `results` (dict)
  The results computed in the example, `{name: value}`, with the names
  of the stored results.

**Returns**

- bool
  True if the data are the original ones and every result agrees with
  the stored one within the tolerance of the problem. One line is
  printed in every case.

**Notes**

The stored results belong to the original data. If any datum was changed,
nothing is compared: the function says so and returns False.

### to_plain

`to_plain(results)`

Convert results to plain Python numbers, lists, strings and booleans.
